# CLAUDE.md Maintenance Sweep

## Overview

`makewhatis/rhapsody` has 25 nested `CLAUDE.md` files (root + 24 subdirectories), generated by a
live-composed Claude Code `Workflow` run (PR #35). They are snapshots: as code changes underneath
them, individual files can go stale — a renamed function, a changed placeholder name, a directory
that no longer exists, a new crate with no file at all. This skill finds and fixes that drift with
*targeted* edits, not a full regeneration of the tree.

Run this only when the ticket that dispatched you exists specifically to run this sweep. If you
were dispatched for unrelated feature work and happen to notice a stale CLAUDE.md nearby, that's
out of scope for this skill — leave it and mention it in your handoff notes instead.

## Step 1 — scoped structural discovery

Find the newest commit that touched any existing `CLAUDE.md`, then look at everything that changed
since:

```bash
newest_commit="" newest_ts=0
for f in $(git ls-files '*CLAUDE.md'); do
  ts=$(git log -1 --format=%ct -- "$f")
  if [ "$ts" -gt "$newest_ts" ]; then
    newest_ts=$ts
    newest_commit=$(git log -1 --format=%H -- "$f")
  fi
done
git diff "$newest_commit"..HEAD --stat
```

Read that diff's file list for two things:

- **New directories that plausibly warrant a `CLAUDE.md`** — a new crate under `crates/`, a new
  top-level subsystem. Apply the same judgment as the original generation methodology's structure
  step: does this directory have enough non-obvious, non-derivable-from-a-glance behavior to be
  worth a file, at what depth, relative to its nearest existing ancestor `CLAUDE.md`?
- **Existing covered directories that were deleted or gutted** to the point their `CLAUDE.md` now
  describes something that no longer exists.

## Step 2 — per-file drift check

For every existing `CLAUDE.md`, diff its directory since that file's own last commit — not the
global newest one from Step 1:

```bash
for f in $(git ls-files '*CLAUDE.md'); do
  dir=$(dirname "$f")
  last=$(git log -1 --format=%H -- "$f")
  if ! git diff --quiet "$last"..HEAD -- "$dir"; then
    echo "DRIFTED: $f"
  fi
done
```

A file with no output here is skipped entirely for the rest of this sweep — that's what keeps this
"targeted updates," not regeneration. For each `DRIFTED` file, read the actual diff
(`git diff "$last"..HEAD -- "$dir"`) and judge whether it makes any claim in the `CLAUDE.md`
inaccurate, or just touches unrelated lines in that directory. Only files with a real inaccuracy
move on to Step 3.

## Step 3 — fix drift via an inline Workflow

For every file flagged by Step 1 (new/retired) or Step 2 (content drift), author and run a
Claude Code `Workflow` **inline**, via the tool's `script` parameter — **never** write a persisted
`.claude/workflows/*.js` file. Compose the script fresh in this same turn, every time.

The script must, in order:

1. **Draft depth-first.** Process flagged files parent-directory-first, then children — a child
   file's non-repetition check must see its parent's *already-fixed* content, not the stale
   version that was true before this sweep started.
2. **Verify independently.** For each drafted edit, a *separate* agent from the one that drafted it
   checks: no content repeated from an ancestor `CLAUDE.md`, under 200 lines, every claim concrete
   and non-derivable from a quick glance at the code (not restated obvious structure), and the
   exact header `# CLAUDE.md — <path>`.
3. **One bounded redraft** on a failed verification. If the redraft still fails, leave that file
   alone and note it in your final handoff summary for human review — do not merge a low-confidence
   edit.

## Step 4 — normal ticket flow

Commit your changes, open a PR against `makewhatis/rhapsody` the way any dispatched Rhapsody ticket
does, and end your final message with the literal line `HANDOFF: in-review`. There is nothing
sweep-specific about this step — it's the same mechanics every other ticket already uses.
